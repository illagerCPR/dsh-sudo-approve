# dsh-sudo-approve

让 DSH 里的智能体能够执行 `sudo` 命令，但每一次都必须由你亲自输入密码确认。

## 它解决什么问题

DSH 的 bash 工具没有终端，智能体直接执行 `sudo` 只会得到一句 “A terminal is required to authenticate”。这个插件把确认环节搬到浏览器：智能体一旦要执行 sudo，聊天输入框就会被替换成授权面板，列出它准备执行的全部命令；你核对后输入登录密码并点击「允许并执行」，命令才会真正运行。

## 使用流程

1. 智能体发出带 sudo 的命令，输入框变成「需要 sudo 授权」面板。
2. 核对命令列表——行首为 `#` 的是会提权的命令，`$` 是普通命令。
3. 输入登录密码，点击「允许并执行」；不想执行就点「拒绝」（或按 Esc）。拒绝时可以先填一句理由，它会转告智能体，不填也可以。
4. 密码错误时面板会提示，命令不会执行，可以重新输入。
5. 面板默认等待 120 秒，没有操作会自动拒绝，并把结果回告智能体。
6. 面板右上角的按钮可以折叠：折叠后只留下状态条（标题与倒计时），高度与聊天框相仿，方便回看对话；再点一次展开继续操作。

## 行为规则

- 只拦截主会话的 bash 调用。子智能体、后台任务（`run_in_background`）、以及在沙箱会话中运行的 sudo 会被直接拒绝并说明原因。
- 判定方式是「命令里出现 `sudo` / `sudoedit` 这个词」，不看它写在哪个位置：`/usr/bin/sudo`、`exec sudo …`、`env sudo …`、`xargs sudo …`、`bash -c "sudo …"` 都会弹面板；行首是 `#` 的注释行不算。
- 宁可多确认一次也不漏放：只是**提到** sudo 的命令（例如 `grep sudo 日志`、`echo "sudo 用法"`）同样会弹一次面板。只有 `sudo -k`、`-K`、`-V`、`-h` 这种不需要认证的写法会直接放行。
- 当前没有已连接的浏览器页面时立即拒绝，不会静默放行。
- 面板一次只显示一个请求，并行发起的其余请求**排队**：前一笔结清（允许、拒绝或超时）后，下一笔立刻出现在面板上，不需要重新发起，面板标题旁会标出还有几笔在等。队列最多 4 笔，再多直接拒绝。两条已批准的命令同时在跑时，各自持有自己的临时凭据，互不影响。
- 会话运行在 PTC 模式（工具只能从 `run_code` 程序里调用）时，程序里的 sudo 调用同样会弹面板；只是审批等待会计入程序自身的执行预算：面板会在预算耗尽前关闭，剩余时间不够的请求则不弹面板直接拒绝，排在别人后面时也可能因预算用完而放弃。把 sudo 放在简短程序的开头，并且不要同时发起两个 sudo 调用。
- 命令执行期间 sudo 可以重复使用这份凭据（例如 `sudo a && sudo b` 只需确认一次）。
- 一条命令跑超过 60 秒会被 bash 工具提升为后台作业、把结果先还给智能体，此时本次调用的临时凭据已经回收：命令开头那几行 sudo 不受影响，但**后面**再调 sudo 就会失败。所以请把 sudo 写在命令最前面，别把它排在长任务之后。
- 接管方式是往 `PATH` 最前面放一个同名的 `sudo`，所以命令里请写**裸**的 `sudo`。写成绝对路径 `/usr/bin/sudo …` 虽然也会弹面板（照样要你授权），但绕过了接管、拿不到密码，执行时仍会以“需要终端”失败。
- 每次审批都会先作废 sudo 的时间戳缓存、再做一次真实认证，因此 `sudo -n`（禁止任何交互）这类写法会直接失败。请写普通的 `sudo`，由插件代你完成认证。
- 密码只提交给 DSH 宿主进程，不进入对话内容、会话记录，也不写入普通日志。
- 会话权限为 `danger-full-access` 时，插件会向智能体注入一小段说明（sudo 可用、直接写普通 sudo、`-n` 会失败、一次确认覆盖整条命令、拒绝后不要原样重试、面板依次确认故仍建议串行），省得它反复试探；PTC 模式下这段话会换成对应的写法与预算提醒。

## 配置

大部分配置可以直接在 DSH 设置的「sudo 授权」页里改（见下一节），保存后立即生效，不需要重启。

也可以在 DSH 配置的插件条目里设定（`cordis.patch.yml` 的 `config`）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `remember` | `never` | `never` 每次都输入密码；`session` 本次会话内记住密码，之后只需点确认 |
| `timeoutMs` | `120000` | 面板等待时长，超时按拒绝处理 |
| `presenceWindowMs` | `15000` | 多久没有页面轮询就视为「没有已连接的页面」 |
| `allowRemoteDeployment` | `false` | 是否允许在非回环地址访问的部署中接收密码 |

插件条目里的值相当于「安装时的默认值」；设置页里保存的值会覆盖它，点「恢复默认」即可丢弃全部覆盖。

## 设置页面

打开 DSH 设置，左侧导航底部附近有「sudo 授权」一页，可以调整：

- 启用拦截：关掉后不再拦截 sudo（插件仍然加载，但直接放行）；
- 授权粒度：每次输入密码 / 本会话记住；
- 面板超时、页面在线窗口：以秒为单位；
- 允许远程部署接收密码：默认关闭，并附风险说明。

保存后立即对**新发起**的请求生效；已经在等待的请求仍按它开始时的设置处理。覆盖值保存在 `~/.dsh/dsh-sudo-approve.json`（仅本人可读写），删除该文件并重新加载插件即回到安装默认值。

## 安全边界

- 安装本插件等于给智能体开通了一条「经你批准的 root 通道」。它只在 sudo 命令上生效，其余操作完全不受影响。
- 密码由宿主进程短暂保存在内存中，并以仅本人可读的临时文件形式交给 sudo 使用，命令结束立即删除；但被批准的命令本身以你的身份运行，运行期间理论上可以读取这些临时数据。只批准你确实要它执行的命令。
- 默认拒绝在可被非本机地址访问的部署中接收密码：明文网络路径上传输密码不安全。确有需要再打开 `allowRemoteDeployment`。
- 沙箱会话内无法提权，需要把会话权限设为 `danger-full-access` 才能使用 sudo。
- 识别靠命令文本匹配，不是沙箱：刻意拆分拼接（`s=su; ${s}do …`）、先下载脚本再执行之类绕过文本的写法拦不住。它的目标是让智能体每次提权都经过你，而不是防住一个铁了心要绕过的对手。
