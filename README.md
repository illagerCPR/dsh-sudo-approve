# dsh-sudo-approve

让 DSH 里的智能体能够执行 `sudo` 命令，但每一次都必须由你亲自输入密码确认。

## 它解决什么问题

DSH 的 bash 工具没有终端，智能体直接执行 `sudo` 只会得到一句 “A terminal is required to authenticate”。这个插件把确认环节搬到浏览器：智能体一旦要执行 sudo，聊天输入框就会被替换成授权面板，列出它准备执行的全部命令；你核对后输入登录密码并点击「允许并执行」，命令才会真正运行。

## 使用流程

1. 智能体发出带 sudo 的命令，输入框变成「需要 sudo 授权」面板。
2. 核对命令列表——行首为 `#` 的是会提权的命令，`$` 是普通命令。
3. 输入登录密码，点击「允许并执行」；不想执行就点「拒绝」（或按 Esc）。拒绝时可以先填一句理由，它会转告智能体，不填也可以。
4. 密码错误时面板会提示，命令不会执行，可以重新输入。
5. 面板默认等待 120 秒，没有操作会自动拒绝，并把结果回告智能体。
6. 面板右上角的按钮可以折叠：折叠后只留下状态条（标题与倒计时），高度与聊天框相仿，方便回看对话；再点一次展开继续操作。

## 行为规则

- 只拦截主会话的 bash 调用。子智能体、后台任务（`run_in_background`）、以及在沙箱会话中运行的 sudo 会被直接拒绝并说明原因。
- 判定方式是「命令里出现 `sudo` / `sudoedit` 这个词」，不看它写在哪个位置：`/usr/bin/sudo`、`exec sudo …`、`env sudo …`、`xargs sudo …`、`bash -c "sudo …"` 都会弹面板；行首是 `#` 的注释行不算。
- 判定之前会先把 shell 的**续行**折叠掉（`\` + 换行在执行时本来就会被删除），所以 `su\` 换行 `do` 这种拆字写法同样会弹面板；面板里显示的也是折叠后的实际命令。
- 宁可多确认一次也不漏放：只是**提到** sudo 的命令（例如 `grep sudo 日志`、`echo "sudo 用法"`）同样会弹一次面板。只有 `sudo -k`、`-K`、`-V`、`-h` 这种不需要认证的写法会直接放行。
- **看不全就不批**：面板最多完整显示 60 行、每行 400 字符。超出这个长度的命令不会弹面板，而是直接拒绝并让智能体改写——因为一次批准覆盖整条命令，你没能看见的部分不能跟着一起执行。
- 当前没有已连接的浏览器页面、或者页面在后台标签里（没有报告自己在前台）时立即拒绝，不会静默放行。
- 批准必须落在一次页面操作之后：面板会先把你的点击/按键上报给宿主，宿主只认**在这次批准之前**已经上报过的手势，请求本身不能给自己作证。隐藏的页面或脚本化的请求会被拒绝。
- 面板只出现在发起请求的那段会话里。若请求属于别的会话，当前会话的输入框下方会显示一条提示（「其他会话有 N 笔 sudo 待确认」+「切过去」），点一下直接跳到那段会话；这是唯一会跨会话出现的东西，面板本身不会。
- 面板一次只显示一个请求，并行发起的其余请求**排队**：前一笔结清（允许、拒绝或超时）后，下一笔立刻出现在面板上，不需要重新发起，面板标题旁会标出还有几笔在等。队列最多 4 笔，再多直接拒绝。两条已批准的命令同时在跑时，各自持有自己的临时凭据，互不影响。
- 会话运行在 PTC 模式（工具只能从 `run_code` 程序里调用）时，程序里的 sudo 调用同样会弹面板；只是审批等待会计入程序自身的执行预算：面板会在预算耗尽前关闭，剩余时间不够的请求则不弹面板直接拒绝，排在别人后面时也可能因预算用完而放弃。把 sudo 放在简短程序的开头，并且不要同时发起两个 sudo 调用。
- 凭据只交给**这一条命令**：它通过该次执行的环境变量生效，同一时间跑在你机器上的其他会话、子智能体、后台作业都拿不到。命令内部可以重复使用这份凭据（例如 `sudo a && sudo b` 只需确认一次）。
- 一条命令跑超过 60 秒会被 bash 工具提升为后台作业、把结果先还给智能体，此时本次调用的临时凭据已经回收：命令开头那几行 sudo 不受影响，但**后面**再调 sudo 就会失败。所以请把 sudo 写在命令最前面，别把它排在长任务之后。
- 靠的是给这一条命令临时准备一个同名的 `sudo`，所以命令里请写**裸**的 `sudo`。写成绝对路径 `/usr/bin/sudo …` 虽然也会弹面板（照样要你授权），但绕过了接管、拿不到密码，执行时仍会以“需要终端”失败。
- 每次审批都会在**开始前和命令结束后各**作废一次 sudo 的时间戳缓存，认证走真实密码校验，因此 `sudo -n`（禁止任何交互）这类写法会直接失败。请写普通的 `sudo`，由插件代你完成认证。注意：无终端的 `sudo -k` 只作用于宿主自己那份记账，不会作废你在终端里已经拿到的缓存。
- 密码只提交给 DSH 宿主进程，不进入对话内容、会话记录，也不写入普通日志。
- 会话权限为 `danger-full-access` 时，插件会向智能体注入一小段说明（sudo 可用、直接写普通 sudo、`-n` 会失败、一次确认覆盖整条命令、拒绝后不要原样重试、面板依次确认故仍建议串行），省得它反复试探；PTC 模式下这段话会换成对应的写法与预算提醒。

## 配置

两种改法：改 DSH 配置里的插件条目（`cordis.patch.yml` 的 `config`），或者手写 `~/.dsh/dsh-sudo-approve.json`（仅本人可读写）。后者优先于前者；设置页的「恢复超时与在线窗口」只清掉它里面这两个计时项，安全相关的键会原样保留。

| 配置项 | 默认值 | 能否在设置页改 |
| --- | --- | --- |
| `enabled` | `true` | 否（只读展示） |
| `remember` | `never` | 否（只读展示）；`never` 每次输密码，`session` 本次会话内记住密码，之后只需点确认——**这等于关掉密码这一环**，见下 |
| `credential` | `auto` | 否；`auto` 先看能否借用 sudo 自己的时间戳缓存，不行才准备临时凭据；也可以固定成 `askpass` 或 `timestamp` |
| `timeoutMs` | `120000` | 是；面板等待时长，超时按拒绝处理 |
| `presenceWindowMs` | `15000` | 是；多久没有前台页面轮询就视为「没有已连接的页面」 |
| `allowRemoteDeployment` | `false` | 否（只读展示）；是否允许在非回环地址访问的部署中接收密码 |
| `sudoPath` | 空 | 否；手动指定 sudo 的绝对路径。默认只接受 root 所有、且非组/他人可写的二进制 |

**安全相关的开关只能在文件里改**：设置页能改的只有「面板超时」和「页面在线窗口」。`enabled`、`remember`、`credential`、`allowRemoteDeployment` 若也能在网页上改，任何跑在页面里的脚本（包括第三方插件的前端）都能一键关掉这道门，所以它们被固定在配置里。

## 设置页面

打开 DSH 设置，左侧导航底部附近有「sudo 授权」一页：可以调整面板超时与页面在线窗口（以秒为单位），其余安全项以只读形式展示并注明「请在配置文件里修改」。

面板底部的「恢复超时与在线窗口」只把这两个计时项恢复成安装默认值，不会动 `enabled` / `remember` / `credential` 这些安全开关——它们只能由配置文件决定。

改动立即对**新发起**的请求生效；已经在等待的请求仍按它开始时的设置处理。

## 安全边界

这是「让你每次提权都能看见并点头」的提示门，**不是**权限边界。已知且有意接受的限制：

- 识别靠命令文本里的 `sudo` 字样。刻意拆分拼接（`s=su; ${s}do …`、`s""udo`）、把命令编码后执行、先写脚本再运行、`source`/`eval` 一段别处的文本之类完全不出现这个词的写法，插件拦不住——能拦住它们的是 sudo 自己的密码提示与时间戳缓存策略，而这台机器上无终端时 sudo 问不了密码，所以这类命令通常会直接失败而不是提权成功。（`\` 续行拼接已经不在其列：判定前会先折叠。）
- 批准的命令以**你本人**的身份运行，所以它在运行期间读得到自己的临时凭据、也做得到你本人能做的一切。只批准你确实要它执行的命令。
- 临时凭据会以仅本人可读的临时文件形式存在到这条命令结束（sudo 需要从那里取密码），命令结束立即删除；宿主进程若被强杀，下次启动时会清理残留的临时目录。
- 默认拒绝在可被非本机地址访问的部署中接收密码：明文网络路径上传输密码不安全。确有需要再打开 `allowRemoteDeployment`。
- 页面「在前台」「有手势」这两点由页面自己上报，能挡住后台标签页与无头轮询，但挡不住一段已经能驱动页面的脚本。而且 DSH 的会话 cookie 签名密钥与智能体同属一个用户、存在本机磁盘上，模型读得到它——所以**页面不是对模型设防的边界**，这道门真正的凭据只有你的密码和你亲手点的那一下。安全开关因此只认配置文件。
- `remember: session` 等于关掉密码这一环：输过一次之后，后续批准不再需要密码。默认是 `never`，建议保持。
- 沙箱会话内无法提权，需要把会话权限设为 `danger-full-access` 才能使用 sudo。
- 密码在网页输入框里键入，同源脚本在输入期间就能读到 DOM 里的明文。插件保证它不进对话、不进会话记录、不进日志，但保证不了它不进页面。
